۳ · نگاشت مهاجرت در صورت انتخاب daisyUI

نگاشت یک‌به‌یک پوسته فعلی به daisyUI. چون تمام صفحات از primitives در src/components/ui/ استفاده می‌کنند، تغییر فقط در لایهprimitive و تم اعمال می‌شود — بدون بازنویسی صفحات.

پوسته فعلیمعادل daisyUIنتیجه
--background / --card / --muted --color-base-100/200/300 + --color-base-content فقط مقادیر عوض می‌شوند
--primary / --primary-foreground --color-primary(-content) فقط مقادیر عوض می‌شوند
--muted-foreground (دستی، مستعد خرابی کنتراست) color-mix(base-content 55%) مشتق از سیستم — دیگر قابل خراب‌شدن نیست
--radius: 8/10/12/16 پراکنده --radius-selector / field / box سه توکن به‌جای مقادیر ad-hoc
--shadow-xs/card/elevated/floating --depth + سایه‌های توکن‌محور نردبان ارتفاع استاندارد و نگهداری‌شده
variantهای CVA در primitives .btn .btn-primary .btn-soft CVA نگه داشته می‌شود، مقادیر از کلاس‌ها می‌آیند
dark mode دست‌ساز (بلوک .dark) [data-theme=forehand-dark] دو بلوک تم، صفر CSS سفارشی
رفتار Base UI (dialog، select، …) بدون تغییر صفر ریسک رفتاری
هر دو گزینه کاملاً متن‌باز (MIT) و بومی Tailwind v4 هستند. daisyUI = کمترین ریسک با حفظ رفتار Base UI؛ HeroUI = بالاترین جلوه پیش‌فرض در ازای مهاجرت کامل primitives. صفحه اصلی برنامه در هر سناریو دست‌نخورده می‌ماند.
